# Reflection on Markdown
## Introduction
Markdown is a simple way to format plain texts. Instead of clicking buttons to format texts like in Microsoft Word, Markdown uses symbols typed into the text to create things like headings, bold text, and italics. Markdown is designed to be easy to read, even before the formatting is applied. In this assignment, I will be reflecting on my findings on the *"Questions About the Code"* section of *"Markdown: A Lightweight Markup Language (2004)"* article. 
## Question 1
Markdown is most useful for simple for things such as documents, notes, websites, and online content. Because of its simplicity, there are certain instances that Markdown might be difficult to use. This suggests Markdown sees a document mainly as organized readable text rather than something with a lot of complex structure or design.
Markdown can be used to create: 
* Websites 
* Documents 
* Notes 
* Books 
* Presentations 
* Emails 
* Technical documentation 
## Question 2
Using regular expressions made Markdown simple and practical, but it also created ambiguity. Certain combinations of symbols could be interpreted differently depending on the Markdown program being used. Because there wasn't a strict formal grammar explaining exactly how every situation should be handled, different versions of Markdown started producing different results. CommonMark was later created to make the rules clearer and more standardized so Markdown could be interpreted more consistently. 
## Question 3
Markdown borrowed ideas from things people were already doing in email and and other forms of plain-text communication. This shows that Markdown wasn't created completely from scratch; it turned everyday habits of early internet users and programmers into standard formatting conventions.
## Question 4
Markdown was originally meant to help web writers create HTML, but people realized its simplicity was useful for much more. Now it is used for notes, documentation, academic writing, and even AI inputs and outputs. This shows that once people adopt a tool, they can find uses for it that its creator never planned. When a format becomes infrastructural, its rules become deeply built into other technologies and people's everyday habits. AI is heavily connected to Markdown. **Large language models** are trained on lots of Markdown-formatted content, which is why AI often produces headings, bold text, and lists in Markdown style. 
## Question 5
Markdown was made freely available, which contrasts with Scribe, an older system that became commercialized. **Gruber** could give Markdown away partly because it was lightweight and built on technology that was already widely available. People didn't need expensive hardware or special software—they mainly needed a text editor and access to Perl to run the original converter. The BSD license also allowed other people to freely use and build on Markdown. However, "free" software still depends on people's time, knowledge, computers, internet access, maintenance, and contributions. So even though users don't directly pay for open-source software, there are still forms of labor and resources supporting it behind the scenes.
## Conclusion
Overall, learning about Markdown helped me understand how something so simple can have such a large impact on the way we use technology today. Markdown started as an easy way to format text for the web, but it has grown into something much bigger. This assignment showed me that even simple tools can become important parts of digital culture and change far beyond what they were originally created to do.
